# Pattern Match — Design & Improvement Plan

## 1. Decisions (agreed with Andy)

| Topic | Decision |
|---|---|
| Platform | A plain HTML/CSS/JS folder opened by double-clicking `index.html`. Built on the Mac, run on Windows. No installs, no server, works offline. |
| Board | 6×6 = 36 numbered tiles holding 18 random pairs. The layout is reshuffled every game. |
| Reveal | Concentration-style: the answer image sits **under** the board. Each matched pair fades away and uncovers the part of the picture behind those two cells. |
| Players | Host-run on a big screen. The audience calls tiles and shouts guesses; the host judges them (C = correct, R = reveal). |
| Icons | 18 original flat SVG icons in `icons/`. |
| Answers | Images in `answers/`, listed in `config.js`. One is picked at random each game. |

## 2. Architecture

```
index.html ──loads──► config.js   (window.GAME_CONFIG: icon list, answer list, timings)
          └─loads──► game.js     (state + rules + rendering + keyboard)
          └─links──► style.css   (layout, 3D flip, fade-out reveal)

Board (square, sized to the window)
 ├─ answer-layer   background-image = chosen answer (cover-cropped)
 ├─ grid (6×6)     opaque cells, no gaps → the answer stays hidden
 │    └─ tile      front = number, back = icon; .open / .matched / .miss / .cleared
 └─ banner         end-of-round messages
```

**Why config is a `.js` file:** browsers block `fetch()` of local JSON and can't list a folder when the page is opened from `file://`. A `<script>` tag always loads, so a config script is the simplest way to make the game work anywhere.

**Portability rules followed**
- No libraries, CDNs or build tools. The sounds are generated by the browser (Web Audio), so there are no audio files.
- Relative paths only, and all file names are lowercase with no spaces (Windows ignores case but the web doesn't).
- The fonts fall back to Segoe UI on Windows and San Francisco on Mac.
- It has been tested in Chromium over `file://`. Edge on Windows uses the same engine.

**State model (game.js):** `tiles[]` (key, open, matched), `open[]` (at most 2 tiles), `pairs`, `turns`, `answer`, `over`, `gameId`.
Rules: flip → if two tiles are open, compare them → on a match, mark them matched and clear them after `clearDelayMs` → on a miss, flip them back after `flipBackDelayMs`. Clicking a third tile during a miss skips the wait. `gameId` stops delayed timers from an old round from affecting a new one.

## 3. Icon set

Apple, lemon, fish, cat, snowflake, tree, flower, mushroom, rocket, house, key, umbrella, anchor, music notes, gift, storm cloud, butterfly, ice cream.
Each icon has its own main colour and shape, so players can tell them apart from across a room. All are 100×100 SVG with a transparent background. `tools/make_icons.py` regenerates them.

## 4. Improvement plan

### Phase 1 — Polish for the first live session (small)
1. **Tune difficulty:** choose answer images whose main subject is spread across the board, not just in the middle, so early reveals are fair clues. Test each image by clearing about 6 random pairs and checking whether the picture is still hard to guess.
2. **Content pack:** add 5–10 answer images for the audience (for example Hong Kong landmarks, or security/5G themes for training sessions).
3. **Windows check:** run it once on the target PC and projector at its real resolution, with sound through the room speakers.

### Phase 2 — Better host experience (medium)
4. **Separate host window.** This is the most important one. Right now, **P** shows the answer on the shared screen. Instead, a second window on the laptop (with the projector as an extended display) would show the answer, the full icon map and the controls, while the projector shows only the board. Both windows can use one `window.open()` so it still works from `file://`.
5. **Teams and scoring:** 2–4 named teams take turns. A team keeps its turn while it keeps matching. Points for pairs, a bonus for guessing the picture early (more tiles still covered = more points), and a scoreboard strip.
6. **Round timer / buzzer:** an optional countdown per turn, and a "Guess!" button that pauses play.
7. **Auto config builder:** `build-config.ps1` (Windows, built-in PowerShell) and `build-config.sh` (Mac) scan `icons/` and `answers/` and rewrite `config.js`, so you can add pictures without editing code.

### Phase 3 — Game variety (medium)
8. **Board sizes:** 4×4 for kids and quick rounds, 8×8 for long ones (`gridSize` already supports this; it needs a larger icon library).
9. **Themed icon packs:** switch icon sets per event (for example `icons/animals/`, `icons/security/`).
10. **Hints:** the host can reveal one random extra cell as a hint, which costs points.
11. **Answer "families":** several accepted titles or a category hint shown at the start ("A famous building").

### Phase 4 — Robustness & distribution (optional)
12. **Resume after refresh:** save the round state in `localStorage` so an accidental F5 doesn't lose it.
13. **Offline desktop app:** if a single `.exe` is ever needed, wrap the same files with Tauri (small) or Electron (larger). No code changes are needed.
14. **Hosted copy:** publish to GitHub Pages so remote players can open a URL.
15. **Automated tests:** keep the Playwright smoke test (deck has 18 pairs, match/miss rules, confirmations) and run it before each event.

## 5. Open questions
- Who is the audience (kids, family, colleagues, training attendees)? This affects the answer images and icon themes.
- Are teams or scores wanted, or is it purely a guessing game?
- Will the laptop drive the projector as an extended display? That decides whether the host window in item 4 is possible.
